# Skill: make-a-prototype

**트리거**: 클릭 가능한 프로토타입(앱·웹 흐름) 생성 요청.

**목적**: 실제로 동작하는 인터랙티브 프로토타입을 만들어 흐름과 상태를 검증한다.

## 절차

### 1단계 — 흐름 정의
- 화면 목록 + 화면 간 전이(클릭/입력/조건)를 정리한다. 전이를 놓치지 않도록 노드 맵을 그린다.

### 2단계 — 구현
- React + JSX 인라인 (고정 버전·무결성 해시 — react@18.3.1, @babel/standalone@7.29.0).
- 전역 스타일 객체는 컴포넌트명 기반 고유 이름 사용 (`const terminalStyles = {...}` — `styles` 금지).
- 여러 파일의 컴포넌트 공유는 `Object.assign(window, {...})` 사용. `type="module"` 금지.
- 화면은 디바이스 프레임(ios_frame/android_frame/macos_window/browser_window 스타터)으로 감싸 실제처럼 보이게.

### 3단계 — 상태
- hover / active / disabled / focus / loading / validation 상태를 모든 인터랙티브 요소에 정의한다.
- 버튼 히트 타깃 최소 44px (모바일).

### 4단계 — 검증
- 주요 흐름을 한 번씩 클릭으로 타고, 콘솔 오류 확인.
- 미구현 상태(더미 데이터·미완성 화면)는 명확히 표시한다.

## 규칙
- "타이틀 화면"을 덧붙이지 않는다. 프로토타입은 뷰포트에 맞게 즉시 내용부터 보여준다.
- 추측으로 상호작용을 만들지 않는다 — 의도가 불명확하면 질문.
