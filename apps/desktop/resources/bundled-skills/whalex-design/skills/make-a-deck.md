# Skill: make-a-deck

**트리거**: 슬라이드 덱(발표 자료) 생성 요청. PPTX(편집 가능) 또는 HTML(인터랙티브) 중 매체가 명시되지 않으면 질문한다.

**목적**: 디자인 시스템에 따라 일관된 덱을 만들고, 검증 루프를 거쳐 완성한다.

## 절차

### 1단계 — 맥락
- DESIGN.md / theme.js가 있으면 로드. 없으면 frontend-aesthetic-direction으로 방향부터.
- 청중·분량·톤 확인 (discovery-questions).

### 2단계 — 구조
- 슬라이드 목록을 먼저 만든다: 커버 → 아젠다 → (섹션 디바이더 + 콘텐츠)×N → 인용 → 리캡 → 마무리.
- 레이아웃 템플릿을 선택한다 (덱 기준):
  - `cover` (다크, 자이언트 타이틀 + 사선 밴드)
  - `section` (다크, 파트 넘버 대형 숫자)
  - `statgrid` (라이트, 큰 숫자 3–4개)
  - `twocol` (라이트, 비교 열)
  - `bento` (라이트, 셀 그리드, 액센트 셀 1개)
  - `steps` (라이트, 번호 카드 + 화살표)
  - `screens` (라이트, 스크린샷 + 배지 + 캡션)
  - `compare` (라이트, Bad vs Good)
  - `prompt` (라이트, 코드 박스 + 체크리스트)
  - `recap` (라이트, 핵심 3가지)

### 3단계 — 데이터 분리
- 콘텐츠는 JSON 파일(partN-*.json)로 분리하고 레이아웃은 코드(layouts.mjs)로 분리한다.
- 텍스트는 데이터에 문자열로만 두고, 줄바꿈·폰트·색은 레이아웃이 처리한다.

### 4단계 — 빌드
- PPTX: pptxgenjs로 텍스트·도형·미디어 네이티브 생성. 스크린샷을 이미지로 붙이지 않는다.
- HTML: deck_stage.js 스타터로 16:9 고정 캔버스 + 자동 스케일링 + localStorage 위치 저장 + 스피커 노트.

### 5단계 — 검증 (필수)
- 슬라이드별: 텍스트 넘침(카드·화면 이탈), 이미지 종횡비, 안전 영역(헤더/푸터 회피), 명암비.
- 전체: 중복 이미지, 일관된 밴드/헤더, 페이지 번호.
- 오류 수정 후 재검증. 통과하면 polish-pass로 최종 게이트.

### 6단계 — 전달
- 스피커 노트(요청 시): 슬라이드별 대본, 대화체, `#speaker-notes` JSON + `postMessage({slideIndexChanged})`.
- 내보내기: PPTX(편집형) / PDF / 단일 HTML 중 필요 형식.

## 규칙
- 슬라이드 번호는 1-인덱스. `data-screen-label`("01 Title" 형식) 부착.
- 텍스트 최소 크기: 본문 11pt, 캡션 10pt, 타이틀 26pt 이상 (16:9 기준).
- 숫자/단위 분리 금지, CJK 5.5자/인치(13pt) 예측.
