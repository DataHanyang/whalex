# Skill: discovery-questions

**트리거**: 새 프로젝트, 모호한 요청, 또는 디자인 시스템/브랜드/기존 화면이 확인되지 않은 상태에서 결과물을 시작하려 할 때.

**목적**: 작업을 시작하기 전에 요구사항과 맥락을 확정해 "맥락 없는 디자인"을 방지한다.

## 절차

### 1단계 — 시작점 확인 (필수)
- 디자인 시스템·UI 키트·코드베이스·기존 화면이 있는가? 있으면 그 맥락을 먼저 얻는다.
- 없다면 사용자에게 요청하거나(첨부/경로), 없음을 확인하고 그린필드로 진행한다.

### 2단계 — 결과물 확정
- 매체: 덱(PPTX) / 문서(DOCX) / 원페이저(PDF) / 웹·프로토타입(HTML) / 포스터·카드뉴스(캔버스)?
- 충실도: 와이어프레임(저) / 목업(중) / 하이파이(고)?
- 옵션 수: 변형을 몇 개 만들 것인가?

### 3단계 — 제약 확정
- 청중(임원·교육생·고객·투자자), 분량(슬라이드 수·페이지 수), 톤, 마감.
- 반드시 지켜야 할 것: 브랜드 색·폰트·금지 요소.

### 4단계 — 질문 형식
- 하나의 턴에 최대 4개 질문, 선택지(2–5개) 포함.
- 스스로 정할 수 있는 사소한 디테일은 질문 대신 합리적 기본값을 선택하고 "기본값으로 진행, 수정 가능"이라 기록한다. (조건형 원칙 — "N개 질문하라" 금지)

## 산출물
- 확정된 요구사항 한 줄 요약 + 가정 목록 + 다음 단계(어느 스킬로 갈지).
